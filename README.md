# השקיה — אפליקציה לניהול השקיית העציצים

אפליקציית React Native (Expo) בעברית, שעוקבת אחרי כל עציץ ואדנית, אומרת כל
יום מה צריך מים, שולחת התראה לטלפון, מתחשבת בגשם ובחום באזור שלך, וכותבת
תזכורות חוזרות ליומן Google.

## מה האפליקציה עושה

**מסך "היום"** — מה דחוף עכשיו, ממוין מהעציץ שהכי מאחר. מראה גם כמה מים
בסך הכל צריך להיום, כדי שתדע אם לקחת כוס או דלי. כפתור "השקיתי" מאפס את
הטיימר ונרשם בהיסטוריה; "דחה ליום" מזיז את התור קדימה בלי לטעון שהשקית.

**מסך "העציצים"** — כל העציצים, עם חיפוש וסינון לפי חדר.

במסך הריק יש כפתור **"הוספת הגינה שלי"** שמוסיף את שתים-עשרה האדניות של
הגינה בלחיצה אחת, במקום להקליד כל אחת בנפרד. הנפחים שם הם הערכה מהתמונות
וכדאי לתקן אותם; כל השאר נגזר מסוג הצמח.

**מסך העציץ** — כל הנתונים, היסטוריית ההשקיות והדישונים, סנכרון ליומן,
עריכה ומחיקה.

**הגדרות** — התראות, מזג אוויר ומיקום, בחירת היומן שאליו נכתבות התזכורות,
שעת התזכורת, סנכרון מלא וייצוא קובץ ‎.ics‎.

## ארבע החלטות שכדאי להכיר

**עונתיות.** בחורף הצמחים שותים הרבה פחות. לכן לכל עציץ יש שתי תדירויות,
והאפליקציה בוחרת לבד לפי החודש: אפריל–אוקטובר = קיץ, נובמבר–מרץ = חורף.

**כמות מים לפי נפח.** השקיה יסודית מרטיבה את כל גוש השורשים בלי שרובה
תצא מהניקוז — בערך 15% מנפח המצע. אדנית 70 ליטר מקבלת 10.5 ליטר. לכל סוג
צמח יש יחס משלו: במבוק צמא יותר ללִיטר מצע, לבנדר הרבה פחות.

**כמה צמחים באדנית.** שלושה ברושים באדנית אחת מרוקנים אותה מהר יותר
מאחד, אבל לא פי שלוש — שורשים צפופים נשארים קטנים יותר משורש שקיבל את כל
האדנית לעצמו. לכן התדירות מתחלקת בשורש הריבועי של מספר הצמחים: שלושה
ברושים הופכים מרווח של 5 ימים ל-3. כמות המים לא משתנה — אתה משקה את
האדנית, לא כל עץ בנפרד.

**מזג אוויר.** הנתונים מגיעים מ-Open-Meteo, שירות חינמי שלא דורש חשבון
ולא מפתח API, ומקבל רק קואורדינטות. שני אפקטים נפרדים, שניהם נמדדים
במילימטרים של מים:

- *ביקוש.* ה-API מחזיר ET0 — כמה מ״מ מים המצע מאבד ביום. אם הימים הקרובים
  חמים או יבשים **מהנורמה של המקום הזה**, אותה אדנית מתרוקנת מוקדם יותר
  והמרווח מתקצר באותו יחס (ומתארך כשקריר ולח). היחס חסום בין 0.6 ל-1.6,
  כדי שתחזית חריגה אחת לא תהפוך את הלוח.

  *הנורמה נמדדת מקומית*, מ-30 הימים האחרונים באותן קואורדינטות, ולא
  מקבוע ארצי. זה לא ניואנס: גינה בגובה 600 מ׳ בשולי מדבר יהודה מאבדת
  יותר מים ביום מגינה בתל אביב — 4.11 מ״מ מול 3.49 בממוצע — למרות
  שהטמפרטורה שם נמוכה ב-1.6 מעלות, כי האוויר יבש יותר והרוח חזקה הרבה
  יותר. מדידה מול קבוע חופי הייתה מסמנת כל יום רגיל שם כגל חום ומקצרת
  לצמיתות כל מרווח — ספירה כפולה של אקלים שהמשתמש כבר לקח בחשבון כשבחר
  את המרווח. מול הנורמה של המקום עצמו, רק מזג אוויר חריג באמת מזיז משהו.
  (הקבוע הארצי נשאר כנפילה אחורה, עד שמצטברת היסטוריה מקומית.)
- *היצע.* גשם שירד ביומיים האחרונים או שצפוי מחר הוא מים שלא צריך לשאת.
  חלוקת המ״מ בביקוש היומי הופכת אותם לימי דחייה. גשם מתחת ל-3 מ״מ לא
  נספר — הוא רק מרטיב את פני הקרקע ומתאדה. גשם לעולם לא קונה יותר ממחזור
  השקיה שלם, כי לאדנית יש גבול כמה היא מחזיקה.

כל זה חל **רק** על עציצים שסומנו "בחוץ". לעציץ בסלון אין קשר לגשם.

**קור.** בגובה ובפנים הארץ לילה בהיר בחורף יורד הרבה מתחת למה שאותו תאריך
מביא בחוף, והדרים באדנית הם מהראשונים לסבול. כשצפוי לילה של 2° ומטה
בשלושת הימים הקרובים, מסך "היום" מציג אזהרה — השקיה בערב שלפני מרטיבה את
האדמה, וקרקע לחה מחזיקה חום ומגינה על השורשים. האזהרה **מונה בשם** את
הצמחים שבאמת בסכנה: לימון, שפלרה וסוקולנטים כן, ברוש וגרניום לא.

**התראות.** התראה אחת בבוקר עם כל מה שצריך מים, לא התראה נפרדת לכל עציץ —
בוקר שאומר "3 אדניות · 30.5 ליטר" מניע לפעולה, חמישה זמזומים נפרדים הם
רעש. ההתראות מחושבות מחדש מאפס בכל פעם שאתה משקה, מוסיף עציץ, משנה הגדרה
או שהתחזית מתעדכנת, כי כל אחד מאלה מזיז את התאריכים. אלו התראות מקומיות
שמתוזמנות במכשיר, בלי שרת ובלי חשבון.

**איך התזכורת מגיעה ליומן Google.** האפליקציה לא מתחברת ל-Google ולא מחזיקה
טוקן. היא כותבת אירוע חוזר ליומן של המכשיר, וחשבון Google שמחובר לטלפון
מופיע שם כיומן שאפשר לכתוב אליו — כך האירוע מסתנכרן ליומן Google שלך
כרגיל. בנוסף אפשר לייצא קובץ ‎.ics‎ ולייבא אותו ל-Google Calendar בדפדפן,
או לשלוח אותו למי שמשקה במקומך בזמן חופשה.

כל שאר הנתונים נשמרים במכשיר בלבד (AsyncStorage) ולא נשלחים לשום שרת.
הבקשה היחידה שיוצאת החוצה היא לשירות מזג האוויר, והיא נושאת רק קואורדינטות
— בלי שם, בלי מזהה ובלי רשימת העציצים.

## הרצה

```bash
npm install
npx expo start
```

סרוק את ה-QR עם אפליקציית **Expo Go** בטלפון. יומן, מיקום, התראות ותמונות
דורשים הרשאות שהמכשיר יבקש בפעם הראשונה.

שתי מגבלות של Expo Go שכדאי להכיר: התראות מקומיות לא נשלחות במדמה
(simulator) אלא רק במכשיר אמיתי, ובאנדרואיד תזמון התראות ב-Expo Go מוגבל.
לשימוש יומיומי כדאי לבנות אפליקציה עצמאית.

לבנייה לאפליקציה עצמאית (‎.apk‎ / App Store):

```bash
npx eas build --platform android
```

## בדיקות

```bash
npm test        # 136 בדיקות יחידה
npm run typecheck
```

הבדיקות מכסות את כל הלוגיקה הטהורה: גבולות העונות, חישוב מועד ההשקיה הבא,
מיון לפי דחיפות, מעבר שעון קיץ/חורף, חישוב מים לפי נפח אדנית וצפיפות
צמחים, התאמת מזג האוויר (גשם, גל חום, נורמה מקומית מול קבוע ארצי, חסימת
האפקט לעציצים בבית, חסמי היחס), זיהוי קור, תזמון ההתראות, ובניית קובץ
ה-‎.ics‎ כולל קיפול שורות לפי RFC 5545 בלי לשבור תווים בעברית.

שלוש בדיקות נכתבו אחרי שתפסו באגים אמיתיים: גשם של היום נספר פעמיים — גם
כ"ירד" וגם כ"צפוי" — כך שטפטוף של 2 מ״מ חצה את סף ה-3; עציץ שהיה צריך מים
היום, כששעת ההתראה כבר עברה, נדחה במחזור שלם במקום למחר בבוקר; והנורמה
הארצית קיצרה מרווחים לצמיתות בכל מקום שאקלימו שונה מהחוף. על האחרון יש
בדיקת נסיגה שמוודאת שיום רגיל בהרים כבר לא מזיז כלום, ושהתנהגות הקבוע
הישן אכן הייתה מקצרת אותו.

## הערה על כיוון הטקסט

הממשק כולו עברית, אבל ה-RTL נעשה במפורש בכל סגנון (`row-reverse`,
`textAlign: 'right'`) ולא דרך `I18nManager.forceRTL`. לכן ה-app מכבה את
ה-RTL האוטומטי של מערכת ההפעלה — אחרת שני המנגנונים היו מבטלים זה את זה
והממשק היה מתהפך בחזרה לשמאל-לימין במכשיר שמוגדר לעברית.
